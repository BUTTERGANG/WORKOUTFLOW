# Critical Code Issues & Fixes

## 🔴 CRITICAL ISSUES (Must Fix Before Launch)

### Issue 1: UUID Generation Method is Wrong ⚠️

**Location**: `shared/schema.ts` - ALL tables

**Problem**: Using `varchar` with `sql\`gen_random_uuid()\`` is incorrect
```typescript
// ❌ CURRENT (WRONG)
id: varchar("id").primaryKey().default(sql`gen_random_uuid()`)
```

**Impact**:
- UUIDs are being stored as strings in `varchar` columns
- This wastes space (36+ bytes vs 16 bytes for native UUID)
- Slower queries and indexing
- No type safety

**Fix**: Use proper `uuid` type from Drizzle
```typescript
// ✅ CORRECT
import { uuid } from "drizzle-orm/pg-core";

id: uuid("id").defaultRandom().primaryKey()
```

**Required Changes**: Update ALL table definitions in `schema.ts`:

```typescript
// Users table
export const users = pgTable("users", {
  id: uuid("id").defaultRandom().primaryKey(), // Changed
  email: varchar("email").unique(),
  // ... rest stays same
});

// Organizations table
export const organizations = pgTable("organizations", {
  id: uuid("id").defaultRandom().primaryKey(), // Changed
  name: varchar("name", { length: 255 }).notNull(),
  ownerId: uuid("owner_id").notNull().references(() => users.id, { onDelete: 'cascade' }), // Changed
  // ... rest
});

// Teams table
export const teams = pgTable("teams", {
  id: uuid("id").defaultRandom().primaryKey(), // Changed
  organizationId: uuid("organization_id").notNull().references(() => organizations.id, { onDelete: 'cascade' }), // Changed
  // ... rest
});

// And similarly for ALL other tables
```

**After making changes, you MUST**:
```bash
# Generate new migration
npm run db:push

# Or generate migration file
drizzle-kit generate:pg
```

**⚠️ WARNING**: This is a breaking change. If you have existing data:
1. Export all data first
2. Drop all tables
3. Apply new schema
4. Re-import data (converting varchar IDs to UUIDs)

### Issue 2: Missing PostgreSQL Extension for UUID

**Problem**: `gen_random_uuid()` requires PostgreSQL extension

**Fix**: Create migration to enable extension

**Create**: `migrations/0000_enable_uuid.sql`
```sql
-- Enable pgcrypto extension for UUID generation
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Or for PostgreSQL 13+, use built-in gen_random_uuid
-- No extension needed for PG 13+
```

**Check your PostgreSQL version**:
```bash
# In psql or pgAdmin
SELECT version();

# If version >= 13, gen_random_uuid() works without extension
# If version < 13, you need pgcrypto extension
```

### Issue 3: Authorization Middleware Not Applied to All Routes ⚠️

**Location**: `server/routes.ts`

**Problem**: Many routes don't use authorization middleware properly

**Examples of Issues**:
```typescript
// ❌ Missing tenant verification
app.get('/api/programs/:id', isAuthenticated, async (req, res) => {
  // Anyone authenticated can access ANY program
  const program = await storage.getProgram(req.params.id);
  res.json(program);
});

// ❌ Missing role check
app.post('/api/programs/:programId/weeks', isAuthenticated, async (req, res) => {
  // Athletes could create weeks if they know the programId
});
```

**Fix**: Add proper middleware to ALL routes

```typescript
// ✅ CORRECT - Verify program belongs to user's organization
app.get('/api/programs/:id', 
  isAuthenticated, 
  async (req: AuthRequest, res) => {
    const userId = req.user.claims.sub;
    const program = await storage.getProgram(req.params.id);
    
    if (!program) {
      return res.status(404).json({ message: "Program not found" });
    }
    
    // Verify user has access to program's organization
    const org = await storage.getOrganization(program.organizationId);
    if (org.ownerId !== userId) {
      const userTeams = await storage.getUserTeams(userId);
      const hasAccess = userTeams.some(t => t.organizationId === program.organizationId);
      if (!hasAccess) {
        return res.status(403).json({ message: "Forbidden" });
      }
    }
    
    res.json(program);
  }
);

// ✅ CORRECT - Verify role
app.post('/api/programs/:programId/weeks',
  isAuthenticated,
  requireRole(['admin', 'head_coach', 'assistant_coach']),
  async (req: AuthRequest, res) => {
    // Now we know user is a coach
    // Still need to verify they have access to this program
    const program = await storage.getProgram(req.params.programId);
    // ... verification logic
  }
);
```

**Fix**: ALWAYS filter by tenant context

```typescript
async getUserPrograms(userId: string): Promise<Program[]> {
  // Get user's organizations
  const userOrgs = await this.getUserOrganizations(userId);
  const orgIds = userOrgs.map(o => o.id);
  
  // Return only programs from those organizations
  return await db
    .select()
    .from(programs)
    .where(sql`${programs.organizationId} IN (${sql.join(orgIds, sql`, `)})`);
}
```

### Issue 5: Replit Auth User Context Not Properly Passed

**Location**: `server/replitAuth.ts`

**Problem**: `req.user` only has auth claims, not full user object with role

**Current**:
```typescript
export const isAuthenticated: RequestHandler = async (req, res, next) => {
  const user = req.user as any;
  // user only has { claims, access_token, refresh_token, expires_at }
  // Missing: role, organizationId, teamIds
};
```

**Fix**: Enhance middleware to fetch full user

```typescript
export const isAuthenticated: RequestHandler = async (req, res, next) => {
  const user = req.user as any;

  if (!req.isAuthenticated() || !user.expires_at) {
    return res.status(401).json({ message: "Unauthorized" });
  }

  const now = Math.floor(Date.now() / 1000);
  if (now <= user.expires_at) {
    // ✅ Fetch full user with role and teams
    const userId = user.claims.sub;
    const fullUser = await storage.getUser(userId);
    
    if (!fullUser) {
      return res.status(401).json({ message: "User not found" });
    }
    
    // Get user's teams for authorization
    const teams = await storage.getUserTeams(userId);
    
    // Attach full context to request
    (req as any).currentUser = {
      ...fullUser,
      teams: teams,
    };
    
    return next();
  }

  // ... refresh token logic
};
```

### Issue 7: No Error Handling in Storage Layer

**Location**: `server/storage.ts`

**Problem**: Database errors aren't caught or logged properly

**Example**:
```typescript
// ❌ No error handling
async createOrganization(orgData: InsertOrganization): Promise<Organization> {
  const [org] = await db.insert(organizations).values(orgData).returning();
  return org;
}
```

**Fix**: Add try-catch with proper logging

```typescript
// ✅ Proper error handling
async createOrganization(orgData: InsertOrganization): Promise<Organization> {
  try {
    const [org] = await db
      .insert(organizations)
      .values(orgData)
      .returning();
    
    if (!org) {
      throw new Error('Failed to create organization');
    }
    
    return org;
  } catch (error) {
    console.error('Database error creating organization:', error);
    throw new Error(`Failed to create organization: ${error.message}`);
  }
}
```
